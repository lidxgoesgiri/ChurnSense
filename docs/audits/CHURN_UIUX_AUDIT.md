# ChurnSense — audit UI/UX untuk handoff Gemini

Tanggal audit: 31 Oktober 2026 (Asia/Jakarta). Root aplikasi: `C:/Churn/loop-analytics`.

## Kesimpulan dan batas verifikasi

ChurnSense sudah memiliki alur analitik yang relevan: input manual/CSV, perhitungan metrik, penyimpanan snapshot, grafik, insight, chat, perbandingan, dan ekspor. Prioritas redesign adalah memperjelas status data dan membuat semua alur dapat dioperasikan dengan keyboard sebelum meningkatkan craft visual. Dekorasi saat ini tersebar pada hampir semua komponen sehingga metrik, form, insight, dan history saling berebut perhatian.

Dokumen ini berdasarkan inspeksi source aktual, bukan klaim pada README maupun audit lama. **Verified** berarti struktur/implementasi terlihat langsung dalam file yang disebut. Dampak yang memerlukan browser ditandai **Inferred**; pengukuran/perilaku yang belum diuji ditandai **Not Yet Verified**. Tidak ada skor Lighthouse, hasil screen reader, screenshot lokal, atau kelulusan WCAG yang diklaim oleh dokumen ini. Bukti runtime tambahan, bila tersedia, dicatat terpisah oleh audit utama.

Tidak ada source aplikasi yang diubah dalam audit ini. Status awal repository memuat `?? public/sample-churn-data.csv`; file tersebut bukan hasil audit dan harus dipertahankan.

Severity: **P0** menghalangi penggunaan aman/keutuhan data; **P1** menghalangi tugas penting/aksesibilitas/kepercayaan; **P2** mengurangi efisiensi/konsistensi; **P3** polish. Effort S/M/L adalah estimasi relatif implementasi, bukan durasi terukur. Tidak ada P0 UI yang telah terbukti melalui runtime dalam audit ini.

## Kontrak produk yang harus dipertahankan

- Pengguna memasukkan agregat pengguna dan revenue untuk satu proyek; ini bukan event analytics, cohort engine, maupun predictive churn model.
- Primary action: hitung metrik dari input yang valid; kemudian pahami hasil, simpan snapshot bila DB tersedia, dan minta insight/chat bila dibutuhkan.
- Nilai rasio internal tetap 0–1; presentasi dapat berupa persen. `estimatedLtv === null` tidak boleh dikonversi menjadi angka nol atau nilai finansial pasti.
- History adalah snapshot tersimpan, bukan daftar customer. Tanggal snapshot tidak otomatis merupakan periode billing atau periode pengukuran.
- Bahasa UI saat ini Inggris; laporan ini Bahasa Indonesia. Jangan mengubah seluruh bahasa produk tanpa keputusan terpisah.
- Light/dark mode sudah merupakan fitur; keduanya harus tetap berfungsi. Sage/pastel-blue dari identitas mark perlu diterjemahkan menjadi semantic tokens yang terbaca, bukan semua teks diberi pastel.

## Hal yang sudah baik dan perlu dipertahankan

- `ProjectForm` sudah memiliki visible labels, `required`, integer step untuk user counts dan decimal untuk revenue (`project-form.tsx:54–82`). Perbaiki domain errors tanpa membuang native behavior.
- Chart tidak merekayasa tren dari satu snapshot; menampilkan bar dan pesan kebutuhan history (`retention-chart.tsx:76–98`). Pertahankan truthfulness ini.
- Table dan risk badge memakai teks, bukan hanya warna; data table sudah mempunyai accessible name dan horizontal scroll wrapper (`retention-table.tsx:35–68`).
- Delete memakai dua langkah confirm/cancel (`projects-history.tsx:31–43,83–113`); perbaiki pending/failure/focus, jangan kembali ke one-click delete.
- CSS punya focus-visible ring dan reduced-motion baseline (`globals.css:70–75,320–331`); `AnimatedMetric` punya reduced-motion hook (`animated-metric.tsx:26–34`).
- Insight fallback diberi label Rule-based (`ai-insight-card.tsx:47–50`); LTV null diberi konteks no churn (`metrics-summary.tsx:95–139,169–177`).
- Chat storage dimaksudkan scoped per user+project (`ai-chat.tsx:22–25,51–70`); jangan memindahkan menjadi storage global saat redesign.
- Error boundary, route loading, dan toast live region sudah ada. Integrasikan dengan state yang lebih jujur dan layout baru, bukan menghapus resilience tersebut.

## Rencana validasi yang belum dijalankan di audit source ini

Semua berikut berstatus **Not Yet Verified**, bukan pass. Gemini harus merekam bukti setelah implementasi dan memisahkan baseline dari hasil akhir.

1. Jalankan primary journey tanpa pointer: landing → sign-in gate → valid/invalid input → dashboard → CSV browse → calculate → insight → compare → export → cancel/confirm delete. Gunakan akun/fixture non-produksi dan jangan mengubah data produksi untuk audit.
2. Render matrix 375×812, 768×1024, 1440×900 serta 320px compact/200% zoom bila relevan. Uji dengan email panjang, judul proyek panjang, 0/1/2/50 history, payload terbesar yang diizinkan, dan chat sangat panjang. Page overflow adalah gagal; intentional table scroll harus berlabel dan tetap operable.
3. Cek light/dark, normal/high zoom, reduced-motion, focus ring, Tab/Shift+Tab/Escape/Enter/Space dan touch target. Ukur critical contrast pairs pada layer sesungguhnya; target 4.5:1 teks normal dan 3:1 teks besar/control boundary bila berlaku.
4. Validasi state sukses/gagal terpisah: calculate sukses/save gagal; DB unavailable; API timeout; expired session; rate-limited AI; streaming putus; parsing CSV partial success; delete ditolak. Tidak boleh tampil `No saved projects` untuk request yang gagal.
5. Chart/table harus menunjuk snapshot yang sama; uji angka nol, ribuan separator, negative delta, equal delta, null LTV, same-name snapshots, timestamp yang sama hari. Jangan mengubah rumus untuk mengejar tampilan.
6. Gunakan `npm run lint`, `npm run typecheck`, `npm run test`, dan `npm run build` sesuai kontrak repository ketika fase implementasi diizinkan. Hasil historis LOOP.md bukan bukti run saat ini. TestSprite/live deployment merupakan fase terpisah dengan data uji terkontrol.
7. Ukur performance melalui metode yang dicatat. Target desain LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 belum merupakan hasil audit. Jangan memakai satu Lighthouse run sebagai klaim field Core Web Vitals.

## Urutan implementasi yang disarankan

1. Perbaiki UX-01–05, UX-07–08: keyboard upload, dialog lifecycle, delta, feedback persistence, outcome form, landmark, dan copy terbukti.
